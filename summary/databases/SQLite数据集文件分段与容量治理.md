# SQLite 数据集文件分段与容量治理

更新时间：2026-10-23 16:12

把一个逻辑表写入多个 SQLite 文件时，需要把**逻辑表 ID、当前文件和已封存文件**的关系持久化。此项目在 `data` 数据库中使用 `__dataset_file_storage_meta`：

```text
tableId → Current 文件（写入、常规查询）
        ↘ Closed 文件（保留历史，按文件数淘汰）
```

切段不是单纯改文件名：先创建并迁移新库，再在元数据事务中将旧 `Current` 改成 `Closed`、插入新 `Current`，最后替换对外连接。元数据和文件系统不能由同一 SQLite 事务原子提交，因此失败路径要清理新建文件，并让数据库记录与可访问路径保持可检查的一致性。结构变化、文件缺失、重名和路径变化也要分别处理。

## 两种限额语义

| 模式 | 达到记录数或大小上限 | 已封存文件 |
| --- | --- | --- |
| 单文件 | 删除最旧记录，继续复用当前文件 | 不产生新分段 |
| 分段 | 封存当前文件，创建新文件 | 最大文件数超限时删最旧 `Closed` |

文件数上限应把 `Current` 计入总数，但 `Current` 不能作为淘汰对象。按存储时长清理旧行时，此实现只清理 `Current`，不改动封存段。

高频写入时，不宜每条记录都执行 `COUNT(*)`：可在成功写入后维护内存计数，达到阈值再读数据库真值，另以周期任务校准脚本直写等未经过计数器的写入。

## 文件大小、WAL 与清理

- SQLite 删除记录后，数据库文件通常不会立即缩小；空闲页留给以后复用。`VACUUM` 会重写数据库，不能当作每次超限的廉价清理步骤。
- 此实现先用主 `.db` 文件大小做快速门槛；单文件模式再用 `(page_count - freelist_count) × page_size` 估算有效页面占用。该值包含表和索引页面，不等于业务净数据大小。
- `-wal` 与 `-shm` 是运行期辅助文件。诊断磁盘实际占用时要查看它们；当前单文件数据量限制不把其短时波动算进有效页面阈值。不要把“有效占用下降”误写成“物理文件立即缩小”。
- 宽表高频写入时，只删除刚超出的少量行可能让占用持续增长。此实现一次清理预留约 20% 容量，避免每次新写入都立即触发清理；实际比例仍应按负载和设备测量。

文件名后缀的时间精度是切段能力的一部分：若两次触发生成同一目标路径，当前实现会跳过第二次切段。互斥锁只保证切换串行，不能保证每次触发都产生一个新文件。
