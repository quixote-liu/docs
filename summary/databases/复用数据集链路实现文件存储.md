# 复用数据集链路实现文件存储

更新时间：2026-10-23 16:12

一个历史采集表若在模型上仍是数据集表，只是增加了文件存储配置，就应优先复用数据集的采集、迁移、CRUD 和查询入口。另起一套“历史采集文件写入”流程，容易漏掉原有的启停、触发、周期、连接状态等条件。

本项目在加载配置时重组数据源，而不是在每次写入处重复判断：

```text
SQLite:  文件存储表 → 独立 data_<表名> 数据源 → 对应 Current 连接
         普通数据集表 → 原 data 数据源
PostgreSQL: Runtime 历史采集表 + 普通数据集表 → 同一 data 数据源
```

这样不同数据源的主要差异落在连接选择，表迁移与 `Create` 等常规操作可以复用。识别历史采集表应看历史策略的 `tableId` 映射，而非“表启用了文件存储”这一条件：普通数据集也能启用文件存储。

职责边界：

- `FileStorageManager` 管理 `Current` / `Closed` 元数据、文件名、连接和限额；采集器只决定何时保存或触发切段。
- HTTP 查询入口决定走原历史查询还是数据集查询；数据集查询用策略关联表，再用 `VariableId` 对齐请求变量与物理列。
- Runtime 的历史变量快照初始化可通过窄接口请求最新值，但持续历史查询无需绕 Runtime 再注册一层 provider。
- Python 模板通过 Go 同步的 Current 文件路径获取数据库连接；切段后路径更新必须跟随连接切换。

动态索引变量的实际索引可能变化，长期保存触发绑定时应保留稳定 Path，处理变更事件时再解析为当前真实索引。文件名绑定变量也应在能访问 Runtime Profile 的初始化阶段求值。
