# Linux 块设备、分区与挂载

更新时间：2026-11-03 10:36

## 先区分四个层次

| 概念 | 负责什么 | 示例 |
| --- | --- | --- |
| 块设备 | 提供可按逻辑块寻址的存储空间，可为物理或虚拟设备 | /dev/sdb、/dev/mmcblk0 |
| 分区 | 将父设备的一段范围划给一个独立用途，由分区表描述 | /dev/sdb1 |
| 文件系统 | 组织文件名、目录、数据位置和空闲空间等 | vfat、ext4 |
| 挂载点 | 把文件系统接入当前目录树的入口 | /mnt/disk0、/userdata |

常见关系是“设备 → 分区 → 文件系统 → 挂载点”，但并非每层必需。可直接在整个块设备上建立文件系统，也可叠加逻辑卷、加密等层。一个文件系统也可能有多个挂载入口，不能把挂载点数量直接等同于物理设备数量。

## Linux 命名为什么不同

| 名称 | 含义 | 注意事项 |
| --- | --- | --- |
| sda、sdb | SCSI 磁盘驱动体系下枚举的设备 | USB 存储及部分其他磁盘都可使用，不等于 SD 卡 |
| sdb1、sdb4 | sdb 上编号为 1、4 的分区 | 编号不保证连续，不是盘符 |
| mmcblk0 | MMC 子系统提供的块设备 | 可以是 SD 或 MMC/eMMC，不应只按名字判具体硬件 |
| mmcblk0p9 | mmcblk0 的第 9 分区 | p 分隔设备末尾数字与分区号 |
| mmcblk0boot0/boot1 | eMMC 的独立启动硬件区域 | 同一器件的不同区域，不是用户区 pN 分区 |
| nvme0n1、nvme0n1p1 | NVMe 命名空间及其分区 | n1 表示命名空间，不应简单视作一颗独立物理盘 |
| loop0 | 以文件等为后备的循环块设备 | 常见于磁盘镜像 |
| dm-0 | device-mapper 逻辑设备 | 可用于加密、LVM 等 |
| md0 | 软件 RAID 设备 | 可由多个底层设备组成 |
| zram0 | 使用压缩内存的块设备 | 不等于可断电持久化磁盘 |

sda/sdb 等名字受设备发现与枚举过程影响，重插或重启后可能变化。持久配置可考虑文件系统 UUID、PARTUUID 或 /dev/disk/by-id；三者分别标识不同层次，克隆也可能造成 UUID 重复，不能无条件当作全球唯一身份。

## MMC、SD、eMMC 的特点

- **MMC**：MultiMediaCard，存储卡标准及其相关协议；Linux 的 MMC 子系统管理 MMC、SD 等相关设备。
- **SD / microSD**：常见的可拔插闪存卡；microSD 是外形规格，不是另一种文件系统。容量、速度及耐久度取决于具体卡片，不能只凭“SD”判断。
- **eMMC**：嵌入式 MMC，通常焊接于主板，封装内包含闪存与控制器。控制器处理底层闪存管理，主机按逻辑块访问；通常用于嵌入式设备系统盘。
- **SDIO**：与 SD 接口体系相关的 I/O 设备类别，不一定提供存储；不能把 MMC 子系统中的所有设备都当成块设备。

boot0/boot1 可能保存启动关键数据；其大小和实际使用方式依硬件与引导方案而定。看到启动区域不能推断两个区域都在使用，更不能随意写入或格式化。

## 根分区与 /userdata 为什么不冲突

```text
mmcblk0p7 → /
             ├─ etc/
             ├─ usr/
             └─ userdata/ ← mmcblk0p9 挂载在这里
```

路径解析从根文件系统出发，走到 /userdata 这个挂载点时切换到 p9 的文件系统，因此两个文件系统可以共存。

- p7 与 p9 分别管理自己的空间；在此独立分区布局中，p9 写满不等于 p7 写满。
- 挂载会遮住 p7 中 /userdata 下原有内容，不会将其删除或迁移到 p9。
- 卸载 p9 后，原来的目录内容重新可见。此时继续写 /userdata 可能写到根分区，造成数据位置错乱或根分区写满。
- 不同文件系统之间的移动通常不能享有同一文件系统内 rename 的原子语义，应考虑复制失败和剩余空间。

## 一个 U 盘为何出现两个分区入口

```text
sdb          disk 14.7G
├─sdb1       part 12.8G /mnt/disk0
└─sdb4       part  1.9G /mnt/disk1
```

这表示同一设备的两个分区分别挂载。文件浏览器按分区显示两个入口是合理的，不代表重复识别出两只 U 盘。卷标提示用途但不是证据；例如名称带 PE 不足以证明其启动用途。

“卸载文件系统”“弹出整设备”“断电”和“物理拔出”不是同一操作。应用中的弹出可能联动卸载多个分区，应按实际实现和挂载结果判断，不要从按钮名称推断。无挂载点也不能单独证明设备已安全移除。

## 只读排查命令

```sh
lsblk -o NAME,TYPE,SIZE,MOUNTPOINT
lsblk -f /dev/sdb
findmnt /mnt/disk0
findmnt /userdata
```

不同设备上的工具版本与可用列可能不同；以现场支持为准。FSTYPE 列说明识别到的文件系统类型；vfat 输出本身不足以区分 FAT16 与 FAT32。不要为了识别布局执行格式化或重分区。
